# カテゴリ操作内の代表取引表示

分類行のA列に代表取引の要約を直接表示する。唯一の関連キーは同じ行のH列の代表支出ID。
支出明細A列と完全一致する取引が1件の場合だけ、店舗・支払先、商品名・取引内容、日付、
金額、支払方法、データ元を表示する。0件または複数件なら「代表取引を確認できません」。
日付、金額、取込ID、行番号を関連キーにしない。要約に技術用IDや計上状態を表示しない。

A列の幅は180px、折り返し・上寄せ、行高は表示内容の長さに合わせる。A列と上部4行を
固定する。B列以降の件数、C列のカテゴリ選択、E列の自動分類、F列の実行対象チェックを
維持する。固定境界と交差する旧結合だけを解除し、A4の静的説明文をB4:F4へ移す。
A5の設定リンクはA5に維持し、結合解除で複製されるB5:C5の書式は元へ戻す。
入力、チェック、承認状態、処理結果、行数・順序、保護範囲、支出明細A:Mを変更しない。

支出明細N列の戻りリンクは、現在行の固定支出IDからカテゴリ操作H列を検索する。
リンク元が1行ならそのAセル、複数ならカテゴリ操作一覧へ戻す。共有セルに戻り先を保存しない。
全件展開後は全支出行に同じROW参照式を配置し、A:Mだけの並べ替えでもIDに追従する。
canary段階では既存Nを維持し、対象3 IDの移動先に式が欠けた場合だけ補完する。

## 移行と停止条件

`Category navigation UI maintenance`は既存の`kakeibo-production`ロックを使う。
本番mainと検証済みSHAの一致が必要。分類・承認・会計処理は呼び出さない。

1. 合成Sheetsの実計算・表示、停止条件テスト、CIを確認し、main CI成功SHAをpinする。
2. `inline-preview`で既存の検証済み閲覧canary 3 IDだけを読取り確認する。
3. `inline-canary`でこの3 IDのA列を切り替え、支出明細A:Mとの6項目一致、ID一致、
   入力・行順・保護範囲の保持、固定表示、不要書込み0件を読戻す。旧シートはまだ削除しない。
4. PCとiPhoneのGoogle Sheetsアプリで要約全文、横スクロール時のA列固定、上部4行固定、
   カテゴリ選択・対象チェックの判別と操作を確認する。PCの狭い表示をiPhone実機確認と扱わない。
   Safariは完了条件に含めず、未確認と報告する。
5. 実機確認後に`inline-expand`を`iphone_sheets_verified=true`で実行する。
   検証済みinline canaryとこのフラグの両方が必要。全分類行のID・内容一致、数式エラー0件、
   入力保持、旧シート参照0件を確認してから全件展開済みと記録する。
6. `inline-retire`で全件を再検証し、全シートの数式・リンク・文字列内リンク・入力規則・
   条件付き書式・グラフ・名前付き範囲の旧シート参照0件、削除直前の状態一致を確認して削除する。
7. 再実行で不要書込み0件、旧シート削除済み、数式と入力保持を確認する。

入力消失、行数・順序変更、ID不一致、旧シート参照残存、支出明細A:Mの変更を検出した場合は
全件展開・削除を停止し、安全な理由コードで報告する。入力を上書きする自動ロールバックはしない。
canary ID範囲は静的なシートメタデータとして保持し、並べ替え・再生成で対象を増やさない。

## 自動更新

カテゴリ操作の再生成はH列のIDからA列の式を生成する。canary外の既存A表示は同じIDから
保持し、別シート向けリンクを新規生成しない。全件展開後は現在の全代表IDに追従する。
更新後の保守で列幅、行高、折り返し、固定表示、N列リンクを復元する。
承認更新は従来どおりB:Lを更新し、A表示を維持する。
旧閲覧シートの生成・更新コードと専用テストは撤去し、移行・参照監査・削除用の識別だけ残す。
