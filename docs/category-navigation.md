# カテゴリ操作内の代表取引表示

分類行のA列に代表取引の6項目を直接表示する。関連キーは同じ行のH列の代表支出IDだけ。
支出明細A列と完全一致する取引が1件の場合に、店舗・支払先、商品名・取引内容、日付、
金額、支払方法、データ元を表示する。0件または複数件なら「代表取引を確認できません」。
日付・金額・行番号を関連キーにしない。技術用IDや計上状態を表示しない。

A列は180px、折り返し・上寄せで、行高を内容に合わせる。A列と上部4行を固定する。
B列の件数、C列のカテゴリ選択、E列の自動分類、F列の実行対象チェックの位置を維持する。
上部の静的説明文はB4:F4、設定リンクはA5に配置する。カテゴリ再生成・銀行確認欄更新後も
同じH列のIDから要約を復元し、固定表示・幅・行高を保守する。承認更新はB:Lだけを更新する。

支出明細N列の戻りリンクは現在行の固定支出IDからカテゴリ操作H列を検索する。
リンク元が1行ならそのAセル、複数なら一覧へ戻す。共有セルに戻り先を保存しない。
全件展開後は全支出行に同じROW参照式を配置し、A:Mだけの並べ替えにも追従する。
金額が数値文字列でも、台帳を書き換えずにSheetsの表示と読戻し期待値を照合する。

## 保守と停止条件

`Category navigation UI maintenance`は既存の`kakeibo-production`ロックを使う。
mainとCI成功済みのSHAの一致が必要で、分類・承認・会計処理は呼び出さない。

- `inline-preview`は読取り専用で、現在の対象IDと保守計画を確認する。
- 必要な場合は`audit_sheet_id`にネイティブのシートIDを指定する。全シートの数式・リンク・
  文字列内リンク・入力規則・条件付き書式・グラフ・名前付き範囲を読取り専用で監査し、
  参照が残る場合は書込みを停止する。この監査はシートやメタデータを変更・削除しない。
- `inline-refresh`は導入済みの要約・固定表示・N列の戻りリンクを保守し、全対象の
  ID一意性と6項目一致、数式エラー0件、再計画の書込み0件を読戻し検証する。
- 未送信入力、チェック、承認状態、処理結果、行順、保護範囲、支出明細A:Mを保持する。
  競合や不一致では停止し、ユーザー入力を上書きするロールバックを行わない。
- 導入済みマーカーのないブックでは保守は書き込まない。canaryマーカーが残るブックの
  自動更新は静的な3 IDの範囲を増やさない。全件展開済みでは現在の全代表IDに追従する。

導入時の既存3 IDの検証、PCとiPhone Sheetsの表示・操作確認、全件読戻しを経て全件展開する。
完了した独立閲覧シートへの依存、生成・更新・移行・削除コードと専用テストは撤去する。
廃止シートの削除は入力保持、全件のID・6項目一致、全シートの参照0件、削除直前の状態一致を
確認した場合だけ行う。Safariは今回の完了条件に含めない。
