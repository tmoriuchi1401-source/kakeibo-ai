# スプレッドシートからカテゴリ処理を実行

カテゴリ操作の B1「入力内容を処理する」をチェックすると、編集トリガーが入力を保存し、
`category-sheet-request.yml` を起動する。受付済みの表示後はシートを閉じてよい。
GitHub の待ち行列と既存 production ロックを通るため、開始時刻の保証はない。
通常のデータ取込、OCR、給与処理は起動しない。

## 操作

1. カテゴリ、今後の自動分類（登録する／登録しない）を入力する。
2. B1 をチェックし、受付済みになることを確認する。
3. 結果は上部に表示される。完了時に実行チェックが外れる。
4. 全月に反映する場合は、カテゴリを選びF列「過去分にも反映（全月）」をチェックしてB1から実行する。同じ条件の「その他／未分類」だけを変更し、分類済みは変更しない。完了した条件は別月分も一覧から除く。
5. 月を限定する場合は、下の期間とプレビューチェックを入力して実行する。固定プレビューの件数・内訳を確認し、「この件数に反映」をチェックして再実行する。

受付後の編集は次回分として保持する。新しい入力を処理したいときは、先の処理が完了してから再実行する。
「登録しない」は既存の自動分類ルールの停止ではなく、その候補の追加登録を見送る選択。

## 初回導入

先に Python/Actions を main に反映し、CI 成功後に `KAKEIBO_VALIDATED_MAIN_SHA` を更新する。
その後 `apps-script/category-submit/Code.gs` と `appsscript.json` を Apps Script に配置する。
既存シートに紐づくプロジェクト、または専用の非共有 standalone プロジェクトに対応する。

所有者が一度だけ以下を設定する。トークンをチャット、Git、シートのセルへ貼らない。

- 対象リポジトリのみ、Actions read/write と必須 Metadata read の fine-grained PAT。
- standalone の場合、Apps Script のプロジェクト設定の Script Properties に
  `CATEGORY_SPREADSHEET_ID` と `CATEGORY_GITHUB_TOKEN` を入力する。
- `configureCategorySubmit` を実行し、Google の Sheets、外部通信、トリガー管理の承認を行う。
- 認証情報は接続確認後に User Properties へ移され、Script Properties のトークンは削除される。
- 既存シートに紐づく場合は、メニュー「カテゴリ操作 → 初回設定」からトークンを入力してもよい。

設定処理はカテゴリ操作の上部に 5 行を追加し、専用の非表示受付シートを作成する。
インストールしたユーザーの権限で編集トリガーが動く。既存の入力と確認チェックは保存される。
受付シートの存在により、従来の定期実行と手動 categories scope は未送信の入力を処理しなくなる。
旧カテゴリ runner は無効のままにする。

### 固定列境界エラーからの復旧（セットアップのみ）

旧コードの `A4:F4.merge()` は固定A列と非固定B列以降をまたぐ。
Sheetsの変更が遅延適用されるため、後続の `setFrozenRows(4)` で例外が表面化する場合もある。
修正版はA4「操作の説明」を独立させ、説明文だけを `B4:F4` で結合する。
A列固定・上部4行固定は維持する。固定解除を復旧手段にしない。

セットアップの再実行は既存の値・数式・リンク・チェック・処理結果・最終更新を保持し、
空欄だけを初期化する。受付の記録・入力スナップショットは書き換えない。
既存トリガーのIDを維持し、対象スプレッドシートの編集トリガーと5分周期の確認トリガーが
不足するときだけ作成する。既存の同種トリガー重複は自動削除せず、確認を求めて停止する。
他ユーザーが所有するトリガーは `getProjectTriggers()` では確認できないため、
**元のインストールユーザー**で作業する。

旧 `A4:F4` 結合に既定の説明文が残っている場合は、結合解除後にそのセルをB4へコピーし、
A4を見出しに戻す。コピー直後の失敗からも再実行できる。
独自の旧説明文、想定外の結合、結合で失われる位置にある値・数式・メモ・入力規則は
自動的に消さず、変更前に停止する。その場合は既存内容を確認してから個別に移行する。
上部5行の追加後／受付シート作成直後／一部トリガー作成後の失敗からも再開し、重複追加しない。

反映手順（本番データの処理とは別作業）:

1. 元のインストールユーザーで既存Apps Scriptを開き、現在の `コード.gs` をローカルへ保存する。
   GitHub版との相違を確認し、独自変更があれば保持して統合する。実コードを確認できない間は
   全文置換しない。プロジェクト・権限・manifest・本番authority・フラグは変更しない。
2. レビュー済み修正版の `Code.gs` のみを既存プロジェクトへ反映して保存する。
   Draft PRの作成やmainへの反映だけでは、Apps Scriptのコードは更新されない。
3. 最初に **`inspectCategorySubmitSetup`** を実行する。これは読み取り専用で、ログは
   真偽値と件数だけ。トークン値、スプレッドシートID、入力内容を出さない。
   `userTokenPresent=true`、`userSpreadsheetMatches=true`、`stagedTokenPresent=false` なら
   既存トークンのUserPropertiesへの移行済みを確認できる。これはトークン有効性や権限の
   再検証ではない。別のユーザーでは元ユーザーのUserPropertiesは見えない。
4. UserPropertiesにトークンがあり対象IDが一致し、`queueBusy=false` であることを確認する。
   今回の実環境情報として報告された受付B2の `complete` は、この条件に対応する。
   トークンがない／対象が違う場合は停止する。再発行・削除・設定値の変更は行わない。
   **`configureCategorySubmit` は実行しない**。既存の初回移行経路にはScriptPropertiesの
   トークンを削除する処理があるため、今回の「トークン削除禁止」下では利用しない。
5. B1のチェック、C1の状態、B2の結果、B3の時刻、A4とB4の内容、6行目以降の入力・数式・リンク・
   チェック、受付の既存記録、現在のトリガーを控える。値をチャットやGitへ貼らない。
   **`installCategorySubmit` を2回**実行し、それぞれの「実行完了」を確認する。
   この関数はカテゴリ受付・workflow dispatchを実行しない。
6. 診断を再実行し `frozenRows=4`、`frozenColumns=1`、`explanationMerged=true`、
   `legacyExplanationMerge=false`、`editTriggerPresent=true`、`clockTriggerPresent=true` を確認する。
   A4見出しとB4:F4説明、既存入力・受付記録・チェック状態、トリガーIDと件数が2回目にも
   変化しないことを比較する。既存の「完了」表示を「入力待ち」に初期化しないのは正常。
7. ここまでを**セットアップ完了**とする。「連携更新手順」の通常操作による受付→完了確認は
   実カテゴリ処理を起動するため別途承認まで保留する。B1を操作しない。
   GitHub workflow dispatch、金融write、原本移動、トークン削除・再発行は復旧検証に不要。

診断と実環境差分確認をまだ実行していない場合、移行済み／本番修正済みとは扱わない。
モックで検証するのは上記の再実行と保存動作であり、Google側の実シート・実ユーザーの検証は別途必要。

## 状態と復旧

入力の JSON と SHA256 は同じ管理スプレッドシートの非表示受付シートに保存する。
GitHub へはランダムな UUID だけを送る。source 入力、シート ID、トークンはログ出力しない。
受付は同時に一件。Python は受付 ID と保存内容を検証し、同じ ID の実行を重複処理しない。
共有の production ロックにより、他の台帳 writer と並行実行しない。

通信の成否が不明な場合は自動再送しない。5 分ごとの確認トリガーは GitHub の実行状態を読み、
キャンセルや終了を確認した場合のみ中断と表示する。単なる待ち時間だけで受付を解除しない。
15 分以上開始しないときは「開始待ち・確認が必要」と表示する。
古い受付を解除する際は、対応する Actions が未実行／終了済みであることを確認する。

台帳変更中の障害では一部反映済みの可能性があるため、エラーと表示し自動再実行しない。
既存のルール登録と過去分の固定 ID・対象照合ガードを保持する。
成功時のみ完了表示を出す。UI 更新直前にも入力を再読し、後からの変更を保持する。

## 検証

`python -m pytest -q tests/test_category_sheet_requests.py tests/test_category_operations.py`

`node --test apps-script/category-submit/Code.test.cjs`

導入後、台帳変更を伴わない状態で B1 の編集イベントから受付・実行・完了まで確認する。
API による B1 書き込みは編集トリガーを発火しないため、実際のシート操作で確認する。
