# 買取レシートの収入計上

購入レシートと買取票は同じ Drive inbox に投入できる。privacy gate は従来どおり医療・給与等を遮断する。通常の買取票は、ローカル OCR が独立した「買取」見出しと合計・現金を確認し、Gemini が `buyback` を返し、日付・店舗・品目合計が検証できた場合にだけ収入明細へ1行記帳する。広告の「高価買取」、ポイント付与、返品はこの経路に入れない。

- 収入明細の既存10列を使用。金額は正の受取額、分類は「その他確認済収入」、口座aliasは空欄、元取込IDは `receipt:<Drive file ID>`、データ元は `receipt_buyback`。支出明細への追加は0件。
- 原本の表示と AI の取引種別が食い違う、または金額等が検証できない場合は要確認として止める。
- 収入IDは元取込IDから決定し、収入明細の既存行と全列照合する。書込み後の読戻しを確認してから取込データに完了行を追加し、Drive 原本を処理済みへ移す。応答喪失後の再実行は同じ収入行を再追加しない。
- 既に誤って支出に記帳した原本は、取込IDが存在するので再投入しても訂正されない。原本・取込行・支出行と収入明細の未計上を照合し、元の支出行を非計上へ変更したうえで収入行を1件追加し、投影と支出一覧を更新する。元の行と ID は監査用に保持する。
- 買取で受け取った現金を後に口座へ入れた場合、銀行入金を別の収入として重複計上しない。口座間・現金間の資金移動として確認する。
