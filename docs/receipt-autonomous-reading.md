# レシートの自動再読取

一般レシートは、明細と支払合計が1円単位で一致すること、日付・店舗名・カテゴリを検証する。不一致なら同じ原本を最大3回まで読み直す。値引き、数量、外税の読み落としを訂正するが、差額調整の架空明細は作らない。訂正で既存の日付・店舗・合計が変わった場合は追加読取で一致を確認する。必要項目が欠けた画像は確認待ちに残す。

Geminiが429/503を返したときは、その原本と後続を受信フォルダに残し、次回の既存定期実行へ回す。会計書込みエラーはこの再試行に含めない。Drive状態の一時的な読取エラーは3回まで再試行するが、書込みの自動再試行・処理中状態の自動解除はしない。

## 医療原本のローカル読取

本番の自動モードは `KAKEIBO_LOCAL_OCR_ENABLED=true` を使う。RapidOCR 3.9.2 / ONNX Runtime 1.30.0と固定SHA256の公開モデルを事前準備する。モデルがない、改変されている、OCRが失敗した場合は保留する。原本を開いた後のモデルダウンロードや医療画像のクラウド送信は行わない。

- 施設名と支払日・発行日を原本内のラベルと位置から抽出する。生年月日・診療日は採用しない。
- 「領収金額」「今回入金額」等の実支払額と、隣接する数字を対応付ける。別の保険総額や点数を支払額へ置き換えない。
- 「医療費請求（領収）書」等の複合見出しも完全一致の文法で認識する。請求書だけの見出し、再発行の案内文、見本は領収書の根拠にしない。
- 金額欄を高さ64ピクセルへ正規化し、別のTesseract OCRでも同額を確認する。有効な数値が食い違った場合は即時保留。数値として読めない場合だけ、高さ48ピクセル・大津の二値化・英語OCRという固定条件で1回再読する。期待額をOCRへ渡さず、桁・小数点・符号の修復もしない。負額記号のある読取は再読で取り除かない。
- 日付・施設・金額・カテゴリが揃い、取消等の記載、競合額、既存支払い候補、本人の入力・保留がない場合だけ自動反映する。
- 既存の1実行1件上限を維持する。残りは次回に再判定する。反映済みの原本は再計上しない。
- 会計の読戻し後、原本の版を再確認して処理済みフォルダへ移す。
- 書込予定を先に保存し、原本・本人入力を再確認してから会計へ書く。書込結果が不明な場合は保留し、重複する自動再書込みをしない。
- 保存する読取結果は会計に必要な項目と根拠コードのみ。患者名・診療内容・OCR全文は保存・送信しない。

ローカル読取を使用しない既存の手動切出し経路は、従来の匿名化・送信権限検証を引き続き使う。ローカル読取成功は画像送信の許可にならない。

## 検証範囲

合成テストで不一致・欠落・原本変更・入力競合・重複・途中失敗・送信境界を確認する。CIでは本番認証情報なしに公開モデルを準備し、ネットワークを無効にして画像処理する。実画像の検証証跡はリポジトリ外に保存し、コミットしない。

実証では許可された一般4件すべてで合計・明細合計が正しく一致した。うち3件は検証成功、原本上部が欠けた1件は日付・店舗名を捏造せず保留した。Geminiの日次上限に達した後、公式のリセット時刻を過ぎて残りの検証を完了した。医療5件は外部接続を無効にした状態で日付・施設・支払額を取得し、支払額は既に照合済みの値と一致した。これらは読取試験で、会計へ再取り込みしていない。全てのレシートを必ず自動確定できるという保証ではない。
